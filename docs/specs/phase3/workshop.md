## What This Document Is

Specification for the Phase 3 ignition workshop and the 8-day clips drumbeat that follows it. Workshop is one of three teaching channels (the other two: app learning block, daily AI mentor). This doc defines its specific job and content.

---

## Job

Workshop is **ignition, not teaching**. 60 min cannot teach iteration discipline. Job is:

1. Identity shift — teams stop thinking "we're building an app," start thinking "we're running experiments."
2. Anchor 3 sticky phrases hard enough to survive 10 days alone.
3. Run one viscerally memorable demo that shows iteration in action.
4. Extract public commitment with stakes.

Methodology lives in the app. Workshop opens the door.

---

## Three Sticky Phrases

These phrases recur across all Phase 3 media. Workshop drills them with stakes attached.

1. **"Pretotype is the question. User is the answer."**
2. **"One variable per cycle."**
3. **"Shut up and watch."**

## The Big Demo — Live Script (Block 0:10–0:25)

This is the workshop's emotional core. Rehearse with planted user 3x before live.

### Setup (1 min)
Instructor on stage with laptop showing pretotype. Planted user (a hackathon staff member, not pre-coached on the pretotype) sits at table with stranger framing. Instructor narrates:
> "I have a real Phase 2 pretotype from an anonymous team. They Proceeded to Phase 3. Their hypothesis: 'students will sign up for our AI tutor if they see one free answer first.' Watch what happens when I test it. I'm going to make every mistake teams make."

### Bad test (4 min)
Instructor pitches the pretotype while testing. Talks over user. Asks leading questions: "do you like this?" "would you use it?" "isn't it cool?"
User responds vaguely positively because of social pressure: "yeah it's nice, I'd probably use it."
Instructor: "Great, hypothesis confirmed!"

### Audience call-out (1 min)
Instructor turns to room: "what just went wrong?" Class shouts: leading questions, pitching, no behavior observed, social pressure, no specific signal. Instructor: "Right. I just collected garbage. Now watch."

### Good test (4 min)
Same pretotype, same user. Instructor:
> "Show me how you'd find an answer to a homework question right now. Don't explain, just do it."

User opens pretotype. Hesitates at sign-up screen. Tries to skip it. Can't. Frowns. Closes browser.
Instructor (silent throughout): "Why'd you close it?"
User: "I don't sign up for stuff before I know what it is."

### Variable isolation (2 min)
Instructor on stage: "What's the ONE variable to change?" Class shouts: remove signup gate, show free answer first, change copy, redesign whole flow, add demo video.
Instructor: "Five guesses. Pick ONE. Test it. If it doesn't move the needle, you've eliminated a hypothesis. Science."
Picks: "remove signup gate, show one free answer, signup after."

### Re-test (3 min)
Modified pretotype (prepared in advance, swap on screen). Same user.
> "Show me how you'd find an answer right now."

User opens. Sees free answer. Reads it. Smiles. Asks "is there more?" Sees signup. Signs up.

### The lesson (sticky phrase moment)
Instructor on stage: "Same pretotype. Same user. ONE variable changed. Different result. **Pretotype is the question. User is the answer. One variable per cycle. Shut up and watch.** Three things. That's the entire workshop."

## Pair Practice — Setup (Block 0:30)

```
PRACTICE PROMPT

Pair with a team you haven't met. One member of your team acts as
a fresh user testing the OTHER team's Phase 2 pretotype.

Rules:
- Tester says nothing while observed user interacts
- "Show me how you'd accomplish [task]. Don't explain, just do it."
- Timer: 4 min observation, 2 min note-taking
- Swap. Repeat.

Capture per session:
- Where did user pause?
- What did they click that you didn't expect?
- What did they say unprompted?
- What's the ONE variable to change next cycle?
```

1. Watch full recording (60 min)
2. Watch all 8 daily clips
3. Pass 5-question quiz (see Quiz section)
4. Mark complete in Self-Learning Platform

### 5-Question Quiz

1. What is Phase 3's job? (a) Build the final product (b) Run hypothesis-driven user tests ✓
2. Per cycle, how many variables should you change? **One**
3. Min fresh testers required, HS track? **3**
4. What is "shut up and watch"? **Observe user behavior silently, don't pitch or talk during testing**
5. What gets you DQ'd? (a) Bad slide design (b) Faking user evidence ✓
